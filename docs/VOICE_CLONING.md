# Local Voice-Cloning & Streaming TTS

Use a local TTS engine that can clone the user’s sample voice once and stream output. For example, **LocalAI’s TTS models** support voice cloning from a reference clip. Pocket-TTS (a lightweight CPU model) “supports voice cloning through … local audio files”【13†L249-L257】. Qwen3-TTS (a larger model) can clone “from reference audio” via an `audio_path` parameter【24†L361-L370】. In both cases you supply your voice sample once (as a WAV/URL) and the TTS uses that “default” voice for all subsequent synthesis. This way the heavy voice conversion step (embedding your sample) happens only at startup, not on every turn.

## Streaming Audio Output

Enable **streaming TTS** so playback starts immediately. Many open-source TTS support chunked output. For instance, LocalAI’s `/tts` API can stream audio as it’s generated by adding `"stream": true` to the request【22†L47-L56】. This lets the agent begin speaking from the first tokens rather than waiting for the full utterance. In practice you would pipe the HTTP stream into an audio player (or directly to the user’s speakers). Because LocalAI (and similar frameworks) break the WAV into PCM chunks, playback can overlap synthesis. The result is that the **perceived latency drops dramatically** even if full generation still takes longer.

You may also consider specialized streaming-capable models. For example, the Dia2 TTS model is designed for conversational use with “streaming generation: begin producing audio without waiting for the full input”【10†L197-L204】. Models like Chatterbox-Turbo or other open-source engines have sub-200ms inference and voice-clone support【10†L247-L255】【12†L0-L4】. In summary, **choose a TTS backend that supports streaming output**, so that each utterance can start playing as soon as the first audio frames are ready【22†L47-L56】【10†L197-L204】.

## Audio Caching and Reuse

Reduce redundant synthesis by **caching fixed phrases or repeated text**. In a conversation, many short replies or common phrases (e.g. “Hello!”, “I’m here,” “Let me check that for you,” sighs, etc.) may reoccur. You can pre-generate these once and reuse them. For example, LiveKit’s TTS docs recommend “pre-synthesized audio” for stable greetings and error messages to “avoid redundant TTS calls”【18†L111-L119】. Likewise, an automatic cache keyed by exact text is possible: store the PCM frames of any utterance and replay them on future matches【18†L158-L167】. PolyAI notes that “cached audio stores previously generated TTS so it can be replayed instantly, reducing latency”【25†L104-L112】. In your system, this means if the LLM ever outputs identical text twice, you can skip TTS entirely and play the saved audio frames instead.

## Implementation Steps

1. **Load and fix the voice sample.** At startup, load the user’s voice sample into the TTS engine (e.g. via `audio_path` in Qwen3-TTS or LocalAI’s config). This clones the voice just once. From now on, every TTS call uses that loaded voice preset.

2. **Enable streaming mode.** When sending text to the TTS, use an API that streams output (e.g. `stream=true` in LocalAI)【22†L47-L56】. Start playback immediately on receiving the first audio packet. Do not wait for the full WAV to be generated before playing.

3. **Chunk the text.** Split long responses into smaller segments. For example, after punctuation or a few words, flush the current text to TTS so it can play partial audio. This makes the agent start speaking sooner, while continuing to synthesize the rest of the sentence.

4. **Cache repeated phrases.** Identify common short replies (greetings, small talk, etc.) and pre-synthesize them at startup, or store them when first generated. If the LLM produces any cached text again, immediately play the saved audio instead of calling TTS again【18†L111-L119】【25†L104-L112】.

5. **Tune voice generation parameters.** If using a heavy model (like GPT-SoVITS or Qwen-Base), consider a smaller “fast voice” model for routine chit-chat, reserving the high-quality model for emotional or critical turns. But *always* keep the same cloned voice. For example, run Pocket-TTS for generic lines (faster) and use Qwen3-TTS only for special cases, to balance quality and speed.

6. **Parallelize synthesis.** While the agent is speaking one chunk, immediately queue the next text for TTS. With streaming, the pipeline works like: Brain → emit text chunk 1 → TTS starts streaming audio1 & playback begins → Brain emits text chunk 2 → TTS streams audio2, etc. This overlap ensures minimal gaps.

By pre-loading the cloned voice and using a streaming TTS backend, the system **never “re-synthesizes the voice sample” every turn**; it only runs fast synthesis on the changing text. Caching and streaming together hide the latency, so even a 1–2 second generation feels instantaneous to the user【22†L47-L56】【25†L104-L112】. The result is a continuous, low-latency conversation in the user’s own voice, without 15–20 second delays.

## Professional Fine-Tuning (AI Friend Custom Voice)

For the highest quality and lowest latency, it is recommended to **fine-tune** a dedicated **V4 model** rather than using zero-shot cloning. This process "bakes" your voice into the model weights, removing the need to provide a reference WAV for every response.
