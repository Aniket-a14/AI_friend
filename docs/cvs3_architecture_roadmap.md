## 🌟 1. Dual-Process Appraisal Engine (Kahneman System 1 / System 2)

### Objective
Split the emotional evaluation pipeline into a sub-30ms reflexive loop (System 1) and a deep semantic analysis loop (System 2).

### Implementation Baseline

#### Target Files to Modify
*   `backend/app/cognitive/appraisal.py` (To be split)
*   `backend/crates/cognitive-rust/src/reflex.rs` (New)
*   `backend/app/agents/brain_agent.py`

#### System 1: Acoustic Reflex (Rust/PyO3)
*   **Trigger**: Immediate audio chunks arriving over NATS (`audio.inbound`).
*   **Logic**:
    *   Compute RMS energy (Loudness).
    *   Compute Zero-Crossing Rate (ZCR) for pitch approximations.
    *   If Energy > Threshold -> Trigger "Startle Reflex" (Immediate interruption signal over NATS `control.interrupt`).
*   **Latency Target**: < 30ms.

#### System 2: Deliberative Semantic Drift (Python/LLM)
*   **Trigger**: Complete NLP transcripts generated by STT.
*   **Logic**:
    *   Pass transcript through a specialized prompt: *"Evaluate the user's utterance for Goal Congruence, Moral Alignment, and Expectedness."*
    *   Calculate deep PAD (Pleasure, Arousal, Dominance) shifts.
    *   Apply ACT-R Base-Level equation to drift the agent's core baseline mood over time.
*   **Latency Target**: < 800ms (Asynchronous, non-blocking).

## 🧠 2. Subconscious Memory Consolidation

### Objective
Transform passive vector retrieval into an active, self-pruning working memory and long-term semantic knowledge graph (Neo4j).

### Implementation Baseline

#### Target Files to Modify
*   `backend/app/agents/pulse_agent.py` (Add background cron triggers)
*   `backend/app/memory/consolidation.py` (New file)
*   `backend/app/state/triple_extractor.py` (Enhance)

#### The Consolidation Algorithm
1.  **Idle Trigger**: `pulse_agent` detects 5 minutes of conversation silence.
2.  **Episodic Fetch**: Query `pgvector` for all messages in the last 24 hours where `consolidated = false`.
3.  **Fact Extraction**: Run the dialogue through a lightweight LLM parsing prompt to yield `(Subject) -[Predicate]-> (Object)`.
4.  **Graph Resolution (Neo4j)**:
    ```cypher
    MERGE (u:Person {id: $user_id})
    MERGE (e:Entity {name: $object_name})
    MERGE (u)-[r:RELATION {type: $predicate}]->(e)
    ON MATCH SET r.weight = r.weight + 1
    ```
5.  **ACT-R Decay & Pruning**: Apply $A = \ln(\sum t_j^{-d})$ to old transcripts. If activation $A$ falls below the retrieval threshold (e.g., -2.0), delete the raw transcript from `pgvector` to save LLM context window space, relying solely on the Neo4j graph for that memory.

## 🎙️ 4. Dynamic Continuous Prosody Mapping

### Objective
Replace rigid, blocky voice parameter presets with a mathematically continuous emotional drift map for highly realistic vocal nuances.

### Implementation Baseline

#### Target Files to Modify
*   `backend/app/voice/prosody.py`
*   `backend/crates/voice-agent/src/prosody.rs` (Migrate logic to Rust)

#### The Mathematical Models
Instead of `if arousal > 0.5: speed = 1.2`, we will use continuous linear algebra applied globally:

```math
\text{Pitch Multiplier} (P_m) = 1.0 + (\alpha \cdot P_{pleasure}) + (\beta \cdot A_{arousal}) - (\gamma \cdot D_{dominance})
```

```math
\text{Speech Rate} (S_r) = 1.0 + (\delta \cdot A_{arousal}) - (\epsilon \cdot P_{pleasure})
```

*   **Constants Definition**:
    *   $\alpha = 0.05$ (Pleasure slightly raises pitch for warmth)
    *   $\beta = 0.15$ (Arousal heavily raises pitch for excitement/stress)
    *   $\gamma = 0.10$ (Dominance lowers pitch for authority)
    *   $\delta = 0.20$ (Arousal directly increases speaking speed)
    *   $\epsilon = 0.10$ (Pleasure relaxes speaking speed)

#### Audio Blending (Overlap-Add)
When parameters change mid-sentence, the Rust `voice-agent` will apply a 10ms crossfade (OLA) between the previous PCM buffer state and the new PCM buffer state to prevent audible popping/clicking.
