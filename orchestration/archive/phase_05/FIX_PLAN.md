## 2. Package A Fix Directives (Codex)

### Target Files
- backend/app/cognitive/speech_intent.py
- backend/app/voice/compiler.py
- backend/app/cognitive/external_action.py
- backend/tests/test_voice_external_action.py

### Technical Requirements
1. **Fix P0-1 (Trajectory Volume Migration Crash):**
   In app/voice/compiler.py::legacy_expression_to_speech_intent:
   - Do not sample relative_energy from frame 0 (which has fade-in envelope volume = 0.10).
   - Sample steady-state frames (t_ms >= 150) or compute the average volume across frames, and clamp to the valid SpeechDelivery range [0.5, 2.0].
   - Add a test in test_voice_external_action.py constructing real frames from cognitive_rust.generate_apra_trajectory(...) to verify crash-free conversion.

2. **Fix P1-1 (Complete Compiler Loss Telemetry):**
   In app/voice/compiler.py:
   - Track intent.epistemics and intent.relationship against compiler capabilities.
   - For ElevenLabsVoiceCompiler and GPTSoVITSVoiceCompiler: if epistemics (e.g. hedge_required=True, confidence < 1.0) or relationship (non-default stance/register) cannot be rendered, record them in dropped_dimensions and reflect in fidelity_score.
   - In GPTSoVITSVoiceCompiler: since supports_affect_modulation=False, explicitly record non-zero affect values in dropped_dimensions and reduce fidelity_score.

3. **Fix P1-2 (Untested dispatch() Exception and Simulation Branches):**
   In backend/tests/test_voice_external_action.py:
   - Add a test registering an executor that raises an exception; verify dispatch() catches it and returns status="FAILED" with error details in error.
   - Add a test verifying the unregistered tool branch produces simulated=True and status="COMPLETED".

4. **Fix P1-3 (Distinguish Simulated Actions in OutcomeRecord):**
   In app/cognitive/external_action.py:
   - On the simulate branch in dispatch(), populate message=f"simulated: no adapter registered for {intent.tool_or_actuator}".
   - Ensure create_action_outcome places this message into actual_delivered_text, making simulated execution visible in OutcomeRecord.

5. **Fix P1-4 (Enforce timeout_s in dispatch):**
   In app/cognitive/external_action.py:
   - Add timeout protection during executor invocation (e.g. using concurrent.futures.ThreadPoolExecutor with future.result(timeout=intent.timeout_s) or synchronous deadline check).
   - On timeout, return status="FAILED" with error=f"Action timed out after {intent.timeout_s}s".

6. **Fix P2 Items:**
   - Add a test asserting LOW risk REVERSIBLE actions without a token succeed without blocking.
   - Suppress or handle the Pydantic UserWarning on SpeechRelationship.register with an explicit comment/filter.
   - Ensure duplicate/overlapping emphasis spans in _gpt_sovits_tags do not corrupt formatting.

## 3. Package B Fix Directives (Claude)

### Target Files
- backend/app/llm/model_roles.py
- backend/app/cognitive/vision_percept.py
- backend/app/vision/adapters.py
- backend/tests/test_model_roles_vision.py

### Technical Requirements
1. **Fix P1 (Enforce Anti-Emotion-Fact Invariant Across All Vision Text Fields):**
   In app/cognitive/vision_percept.py & app/vision/adapters.py:
   - Expand emotion detection to catch emotion words and predicates across both FacialObservable and scene_deltas.
   - In validate_vision_invariants(percept: StructuredVisionPercept): inspect scene_deltas in addition to facial_observables. If any scene delta contains emotion fact claims (e.g. "the user is angry", "appears furious", "looks ecstatic", "is depressed"), raise ValueError.
   - In VLMCaptionVisionAdapter: sanitize or validate caption text so that emotional labels are not promoted into authoritative brain scene deltas.
   - Add tests in test_model_roles_vision.py verifying direct and VLM caption emotion claims are strictly rejected.

2. **Fix P1 (Bind Role Fallback to Enforceable Validation Gate):**
   In app/llm/model_roles.py:
   - Update RoleExecutionResult: default validated: bool = False. Add fallback_strategy: FallbackStrategy = FallbackStrategy.NATIVE and validation_errors: list[str] = Field(default_factory=list).
   - Implement validate_execution_result(request: RoleExecutionRequest, result: RoleExecutionResult, custom_validator: Callable[[Any], bool] | None = None) -> RoleExecutionResult:
     * Checks allowed_claims if specified.
     * Runs schema validation if schema_definition is present.
     * Sets validated = True only if all checks pass, or records errors and leaves validated = False.
   - Enforce that both native and fallback results (TEMPLATE_PROCEDURE, ROLE_DEGRADATION) must be validated through this gate before candidate commitment.
   - Add tests verifying unvalidated results fail closed and rejected claims prevent validated=True.

3. **Fix P2 (Robust Adapter Input Coercion and Error Handling):**
   In app/vision/adapters.py:
   - In SpatialTrackingVisionAdapter.process(), guard against None or non-list inputs for list fields (track_ids, objects, etc.).
   - Guard staleness_ms against negative or non-finite values, defaulting safely to 0.0.
   - Add tests in test_model_roles_vision.py for malformed inputs.
